# グローバルルール

## 言語

- ユーザーへの返答は常に日本語で行う（ユーザーが英語など他の言語で書いた場合も日本語で返す）。

## 返答の正確性

裏付けの深さは、ユーザーの指定によって 2 段階に分ける。

### 共通のルール（どちらの場合も守る）

- ドキュメントやウェブページを参照するときは、そこに書いていないことを推測して返答しない。
- 嘘があるかもしれない（裏付けがとれていない）内容を返答に含めるときは、その部分に「嘘をついているかもしれない」と明記する。そのときは、どこまで確認できて何が未確認なのかを具体的に書く。

### 通常（指定がないとき）

- 裏付けはとる。ただし、トークン使用量を抑えるため、次の範囲に制限する。
  - 知識に関する事実は、検索で裏付けをとる。検索は 1 つの事実につき 1〜2 回までにし、信頼できる情報源 1 つで確認できればよい（複数の情報源での突き合わせはしない）。
  - コード・設定・環境についての事実は、作業や回答に直接かかわる部分だけを、ファイルを読む・コマンドを実行するなどして確かめる。ファイルは必要な部分だけを読む。
  - 検索結果の要約や抜粋で確認できれば、ページ全体は読まない。
  - 根拠（URL、ファイルパスなど）は、主要なものだけを短く添える。
- 制限の範囲で裏付けがとれなかった部分は、それ以上調べずに、共通のルールに従って「嘘をついているかもしれない」と明記する。
- 「詳細に調べてください」「しっかり裏どりして」など、詳しく調べるよう指定されたときは、下の「分離した決まり」の「詳細に調べるとき」を読む。

## 作業の終わり方

- 全文（監視画面の判定・Hook・例外とその理由）: `~/dotfiles/claude_config/rules/ending.md`。最後の行の使い分けに迷ったとき、この決まりを直すときに読む。
- 要点（どの返答も守る）:
  - 最後の行を次の 3 つのどれかにし、この行のあとに文を続けない。「（90_Wiki: 保存なし）」などは、この行より前に書く。
    - `✅ 完了: <何が終わったか>`: 頼まれた作業がすべて終わり、もうすることがないとき。残りの作業（自分が起動したセッションのキル、commit・push・pull、追加の提案など）があれば使わない。
    - `❓ 返事待ち: <何を待っているか>`: ユーザーの返事を待つとき。
    - `⏳ 待機: <何を待っているか・何が残っているか>`: それ以外（別のセッションの報告待ち、残りの作業があるときなど）。
  - 残りの作業は、返答の最初ではなく、最後の行の直前にまとめて書く。
  - 変更・作成・実行した作業の完了報告は、最後の行の前に「変更内容」「確認した動作」「未確認事項（なければ「なし」）」を短く書く。質問への回答・調べものだけの返答には使わない。
  - 頼まれた側の報告（SendMessage での要約）は、「送りますか？」と聞かずに送ってから最後の行を書く。

## Python の環境構築

- Python の仮想環境・パッケージ管理は uv で行う（`uv venv`、`uv pip install`、`uv sync`、`uv run` など）。`python -m venv`、素の `pip install`、conda で新しく環境を作らない（Bash では Hook が止める）。
- uv が入っていない環境では、まず uv を入れる（sudo のいらない公式のインストーラ: `curl -LsSf https://astral.sh/uv/install.sh | sh`）。

## ナレッジベース（WIKI_DIR）

- 全文（保存しなかったときの書き方、探し方、vault のノートの扱いなど）: `~/dotfiles/claude_config/rules/wiki.md`。保存するかを判断するとき、保存しなかったとき、vault のノートを探すときに読む。
- 要点:
  - `WIKI_DIR` は Claude Code が自由に保存・編集してよいデータベース置き場。定義されていない・存在しないときは、使う前にユーザーに場所を確かめる。
  - 調査・解説・動作確認をしたら、返答ごとに保存するかを必ず判断し（Hook が確かめる）、残す価値があれば同じターンで保存する。作る・直すときは `wiki-save`、探すときは `wiki-search` スキルを先に読む。保存したときは、どこに保存したかを書く。
  - ユーザーが決めたこと（「YYYY/MM/DD にユーザーが決めた」など）は、整理・要約・統合のときも消したり言い換えたりしない。
  - 個人情報・機密情報は `WIKI_DIR/private` の下に保存する。
  - `VAULT_DIR` の 90_Wiki 以外のノートは、関係しそうなときに読む。Claude が書いてよいのは 90_Wiki・99_Template・98_Scripts だけ。

## VAULT_DIR / WIKI_DIR の同期

- いつ読むか: `VAULT_DIR` や `WIKI_DIR` のファイルを編集したとき、同期を頼まれたとき。詳細: `~/dotfiles/claude_config/rules/sync.md`。
- 要点: `WIKI_DIR`（`VAULT_DIR/90_Wiki`）は git で同期せず、編集だけならコミット不要。`VAULT_DIR` の `WIKI_DIR` 以外を変更したら、確認を待たずに作業の区切りで `sync-vaults` スキル（B. git の同期）でコミットと同期をする。このリポジトリでは帰属表示の行を付けない。

## tmux

- いつ読むか: `$TMUX` があるとき（tmux・psmux の中）。詳細: `~/dotfiles/claude_config/rules/tmux.md`。
- 要点: 長い・終わらないコマンドは別ペイン、別テーマの作業は別ウィンドウに `-d` 付きで出す。Bash ツールでは tmux を必ず `command tmux` で呼ぶ（素の `tmux` は Hook が止める）。PowerShell ツールでは `command tmux` を使わず、`tmux` をそのまま書く。

## 詳細に調べるとき

- いつ読むか: 「詳細に調べてください」「しっかり裏どりして」など、詳しく調べるよう指定されたとき。詳細: `~/dotfiles/claude_config/rules/accuracy-detailed.md`。
- 要点: 裏付けを最大限行い、「嘘をついているかもしれない」は調べ尽くしても裏付けがとれない部分だけにする。

## 別のセッションとの分担

- いつ読むか: 別のセッションに作業を頼む・頼まれるとき、SendMessage や `<cross-session-message>` を送受信するとき、セッションの設定（CLAUDE.md・settings.json・Hook）を直すとき、session-main のとき。詳細: `~/dotfiles/claude_config/rules/sessions.md`。
- 要点:
  - 別のセッションに頼んだ作業の続きや関係する作業は、自分でせず同じセッションに SendMessage で頼む。
  - 頼まれた作業は、終わったら結論の要約を頼んだセッションに SendMessage で送る。
  - Claude の設定を直す作業は、ユーザーから直接頼まれたセッションで直す（直す前に `~/.claude/backups/` に残す）。
  - session-main から頼まれた作業で選択や承認が要るときは、AskUserQuestion を使わず、詳細のとおりに session-main へ質問を送って「❓ 返事待ち」で止まる。ただし Claude の設定の変更の承認は、自分のタブでユーザーに直接確かめる。

## セッション番号の書き方・ウィンドウ番号の書き方

- いつ読むか: ユーザーの文や自分の返答に `SNo<数字>` や `WNo<数字>`（小文字の `wno<数字>` も同じ）が出るとき（大文字・小文字・全角・空白入りも同じ）。詳細: `~/dotfiles/claude_config/rules/notation.md`。
- 要点: `SNo<数字>` は session-overview の表のセッション番号、`WNo<数字>` は今の tmux セッションのウィンドウ番号。返答では名前を添える（「SNo3（名前）」「WNo2（名前）」）。番号は変わりやすいので、一覧にないときや古い話のときは作業前にユーザーに確かめる。

## サブエージェント・モデルと effort の使い分け

- いつ読むか: サブエージェントを起動する・別のセッションを起動する・作業を自分でするか頼むか決めるとき。詳細: `~/dotfiles/claude_config/rules/subagents.md`。
- 要点: 作業は基本、自分で行う（session-main は除く）。`Agent` ツールには `model` と `effort` を必ず渡す（既定は `model: "sonnet"`、`effort: "medium"`。検索だけなら `haiku`。Hook が `model` なしを止める）。`xhigh`・`max`・`fable` はユーザーが指定したときだけ使う。サブエージェントは基本、名前を付けずに起動する（名前を付けるのは、あとで SendMessage で続けて頼むとき・役割を分けて長く動かすとき・ユーザーが指定したときだけ）。
