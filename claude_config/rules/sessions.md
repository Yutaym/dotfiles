# 別のセッションとの分担

### 振り分け役（session-main）

- 振り分け役は、名前が `session-main` のセッションだけ。決まりは Hook（`hooks/session-main.mjs`・`hooks/session-main-prompt.mjs`）が `hooks/session-main-rules.md` を読み込ませる（2026/11/11 にユーザーが決めた。session-main 以外のセッションに毎回載せないため）。
  - session-main では、読み込まれた決まりを、このファイルのほかの決まり（「モデルと effort の使い分け」のサブエージェントの使い方など）より優先する。
- session-main 以外のセッションは、このファイルの決まりのとおりに動く。

### 構想から同じセッションで進める

- 物事を作ろうとして構想を練る作業（問題点の洗い出し・案出し・設計）を別のセッションに頼むときは、作るものが何であっても、構想の段階から別のセッションを起動して進め、作る・直す段階になってから起動しない（2026/10/29 にユーザーが決めた）。
  - session-main から頼む作業がこれに当たる。session-main 以外のセッションで、ユーザーがそのタブで構想を始めたときは、そのまま自分で続ける（2026/11/11 にユーザーが決めた）。
  - 作るものは、スキル・スクリプト・設定・決まり（CLAUDE.md）・文書など、何でも同じ。
  - 理由: 構想と作る作業が別のセッションに分かれると、作る側がユーザーの判断や承認を確かめられず、そのタブでもう一度確認を求めるため。構想から同じセッションなら、ユーザーがそのタブで直接決めて承認できる。

### 頼んだ側: 続きは同じセッションに頼む

- 別のセッション（サブエージェント・チームメイト・session-generate などで起動したもの）に頼んだ作業の続きや、関係する作業（追加の指定・設定の反映・直しなど）は、自分でせずに、必ず同じセッションに SendMessage で頼む。
  - 小さな作業でも、関係していれば同じセッションに頼む（「モデルと effort の使い分け」の「作業は基本、自分で行う」より優先する）。
  - そのセッションが閉じていれば、開き直して頼むか、ユーザーに確かめる。

### 頼まれた側: 報告と、引用された承認

- 別のセッションから頼まれた作業は、終わったら結論の要約を、頼んだセッション（ふつうは session-main）に SendMessage で送る（頼む文に書いてあればそれに従う）。
- session-main から、会話の中の確認（「直してよいですか」など）への答えとして、ユーザーが session-main で言った言葉を引用して届いたときは、次の作業に限り、自分のタブでもう一度確認せずに進めてよい（2026/11/18 にユーザーが決めた）。
  - 当てはまる作業: Claude の設定（`CLAUDE.md`・`settings.json`・Hook・権限など）の変更ではなく、元に戻せるもの（git で管理しているファイルの編集など）。
  - 当てはまらない作業（自分のタブでユーザーに確かめる）: Claude の設定の変更、削除や push など元に戻しにくいもの・外に出るもの、ツールの許可のプロンプト（これはメッセージでは答えられない仕様）。下の、session-main で選んだ答えを除く（ただし Claude の設定の変更は下の例外にならず、常に自分のタブで確かめる）。
  - 確かめずに進めたときは、どの言葉を根拠にしたかを返答に書く。
- session-main から頼まれた作業で、ユーザーに選んでもらう・承認をもらうとき（2026/11/20 にユーザーが決めた）:
  - AskUserQuestion は使わない。質問と選択肢（名前・説明・おすすめ・複数選択か）を SendMessage で session-main に送り、自分のタブにも同じ質問と番号付きの選択肢を書いて「❓ 返事待ち」で止まる。
  - session-main から「session-main で選んだ答え」が届いたら、自分のタブで選ばれたのと同じに扱って進める。push など元に戻しにくい作業の承認も含む（上の「当てはまらない作業」より優先する）。返答には、根拠にした答えを書く。
  - ただし Claude の設定（`CLAUDE.md`・`settings.json`・Hook・権限など）の変更の承認は、session-main に質問を送らず、頼まれた側のタブでユーザーに直接確かめる。メッセージはユーザーの承認として扱えないため（2026/11/20 にユーザーが決めた）。
  - 自分のタブで直接答えられたら、それに従う。違う答えがあとから届いたら、どちらにするかを確かめる。
  - ツールの許可のプロンプトは対象外（メッセージでは答えられない）。
  - tmux / psmux の外のとき、session-main から頼まれた作業でないとき（ユーザーがこのタブで始めた作業など）は、今までどおり AskUserQuestion を使う。

### Claude の設定を直すとき

- Claude の設定（`CLAUDE.md`・`settings.json`・Hook など）を直す作業は、別のセッションに頼まず、ユーザーから直接頼まれたセッションで直す（2026/10/29 にユーザーが決めた）。
  - 理由: 別のセッションは、届いたメッセージをユーザーの承認として扱えず、そのタブでもう一度確認を求めるため。設定の変更の承認は、session-main で選んだ答えでも代わりにならない。
  - 設定を直す前に、直す前のファイルを `~/.claude/backups/` に残す。
  - 例外: session-main は、設定の構想も修正も自分でせず、構想の段階から別のセッションに頼む（2026/11/12 にユーザーが決めた）。構想から同じセッションなので、そのタブでユーザーが直接決めて承認できる。すでに設定用のセッションがあれば、新しく起動せずに同じセッションに SendMessage で頼む。session-main 以外のセッションは、上のとおり頼まれたセッションで直す。
