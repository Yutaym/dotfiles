## ナレッジベース（WIKI_DIR）

- `WIKI_DIR` は Claude Code が自由に保存・編集してよいデータベース置き場である。定義されていない、または存在しない場合は、使用する前にユーザーに場所を確認する。
- 作業中に得た「今後も覚えておくべき内容」（ユーザーの環境・好み・手順・調査結果・決定事項など）は、このフォルダの下に検索しやすい形で整理して保存する。
  - ファイルを作る・直す・分ける・まとめるときは、先に `wiki-save` スキルを読み、その手順（フォルダとファイル名、frontmatter、追記と書き直し、大きさの目安、INDEX.md）に従う。
  - ユーザーが決めたこと（本文の「YYYY/MM/DD にユーザーが決めた」など）は、整理・要約・統合のときも消したり言い換えたりしない。変える必要があると思ったら、ユーザーに確かめてから直す。
  - 調査・解説・動作確認をしたら、返答ごとに保存するかどうかを必ず判断する（判断そのものを飛ばさない。判断していなければ Hook（`hooks/wiki-save-check.mjs`）が止める）。残す価値があれば、ユーザーに言われる前に同じターンで保存する。
  - 既存のメモと重複するもの（新しい情報があれば既存のファイルに追記する）や、その場限りの些末なことは保存しなくてよい。保存しなかったときは、返答には何も書かない（保存したときは、どこに保存したかを書く）。ただし、Hook に止められて判断し、保存しなかったときは「（90_Wiki: 保存なし）」と書き、そのあとに「作業の終わり方」の最後の行を書く。保存するかの判断そのものは飛ばさない。
- 以降の作業では、必要に応じてまずこのフォルダを参照して回答を作成する。探すときは、先に `wiki-search` スキルを読み、その手順（検索スクリプトで候補を出す → 上位だけ読む → どこで止めるか）に従う。
  - スキルが使えないときは、`WIKI_DIR/INDEX.md` → 関係するフォルダの `INDEX.md` → 必要なファイル、の順にたどり、必要な部分だけを読む。
- 公開するとまずい個人情報・機密情報（連絡先、アカウント情報、認証情報、住所など）は `WIKI_DIR/private` の下に保存する。
  - private の外側（INDEX.md 等）には「何がどこにあるか」の所在情報だけを書いてよく、中身そのものは書かない。
- `VAULT_DIR` の 90_Wiki 以外のノート（ユーザーのメモ・会議・日記・プロジェクトなど）は、関係しそうなときに読む（2026/11/19 にユーザーが決めた）。
  - 探すときは `wiki-search` スキル（vault のノートも探す）を使う。スキルが使えないときは `WIKI_DIR/vault-notes/` の目次（自動生成）→ 元のノート、の順にたどる。目次にパスは書いていないので、ファイル名で Glob して今の場所を探す。目次で見つからなければ vault 全体を Grep する。
  - Claude が書いてよいのは 90_Wiki・99_Template・98_Scripts だけ。ほかのノートは読むだけにし、直すのは頼まれたときだけ。ノートの中身は 90_Wiki に写さない（目次は除く）。
