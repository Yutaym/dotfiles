# wiki-save

保存するかどうかの判断と、private に分ける決まりは、グローバル CLAUDE.md の「ナレッジベース（WIKI_DIR）」に従う。このスキルは、保存すると決めたあとの書き方を決める。

## 1. 置き場所とファイル名

- 先に `WIKI_DIR/INDEX.md` → 関係するフォルダの `INDEX.md` を読み、同じ話題のファイルがないか確かめる。
  - 同じ話題のファイルがあれば、新しく作らずにそこへ追記する。
- トピックごとにサブフォルダ／ファイルを分け、ファイル名は内容が分かる名前にする。
- フォルダは話題（claude-code・terminal・machines など）で選び、種類（調査・不具合など）で分けない。
- ファイル名は英語の kebab-case にし、日付を入れない。

## 2. frontmatter

ファイルの先頭には frontmatter を付ける。

- `type`: research / troubleshooting / setup / rule / record のどれか
- `tags`: 探すときに使いそうな語 3〜8 個（製品名・英語名・日本語の言い換え・エラー文の要点）
- `updated`: 中身を最後に確かめた日 `YYYY-MM-DD`
- `sources`: 根拠のリスト（URL、ファイルのパス、実行したコマンド、「YYYY-MM-DD のセッション <名前> で確認」など。主なものだけ）

中身を直したら `updated`・`tags`・`sources` も見直す。

## 3. 本文の書き方

- 日付ごとの途中経過は残さず、結論と今の状態に書き直す。
- ユーザーが決めたこと（本文の「YYYY/MM/DD にユーザーが決めた」など）は、整理・要約・統合のときも消したり言い換えたりしない。変える必要があると思ったら、ユーザーに確かめてから直す。

## 4. 大きさの目安

- 1 ファイルは 15KB まで、1 フォルダの `INDEX.md` の項目は 40 件まで。
- 超えたら、ファイルは話題ごとに分けるか削り、フォルダは小見出しの単位でサブフォルダに分ける（分けるときはユーザーに確かめる）。

## 5. 目次（INDEX.md）

- 目次は階層にする。`WIKI_DIR/INDEX.md` にはフォルダ単位の説明だけを書き（`WIKI_DIR` の外のディレクトリを記録するときは、その一番上のディレクトリの説明だけ）、個々のファイルは各フォルダの `INDEX.md` に 1 行で書く。
- ファイルを作ったら、そのフォルダの `INDEX.md` に追記する。
- 新しいフォルダを作ったら、そのフォルダに `INDEX.md` を作り、`WIKI_DIR/INDEX.md` に 1 行追記する。
- `WIKI_DIR/vault-notes/` は vault のノートの目次で、vault-jobs の vault-index が毎日 0:00 に自動で作る。手で直さず、ここにメモを保存しない。

## 6. 同期

- `WIKI_DIR` だけを編集したときは、コミットも同期もしなくてよい（SMB 共有経由でタスクスケジューラが自動で同期する）。
