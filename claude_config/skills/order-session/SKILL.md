# order-session

今動いている別の Claude Code のセッションを選び、SendMessage で作業を頼む。
セッションの起動はしない。起動から頼むときは spawn-session スキルを使う。

## 1. 宛先と頼む内容を分ける

引数（またはユーザーの言葉）から、宛先のセッション名と、頼む内容を取り出す。

- 先に `ListAgents` を実行する。1 行目が自分のセッション名、`Peer sessions` の各行が宛先にできるセッションである。
- **宛先:** 一覧のセッション名と一致する語があれば、それを宛先にする（大文字・小文字の違いだけなら一覧の表記に直す）。
  - 一致しないが似た名前があるとき（`claudews-psmx` → `claudews-psmux` など）は、そうだと決めつけず、2. で選んでもらう。そのとき似た候補を先頭に入れる。
  - 自分のセッションは宛先にしない（自分に送ることになる）。
- **頼む内容:** 宛先の名前を除いた残りを、頼む内容とする。何も残らなければ「頼む内容なし」とする。

## 2. 宛先を選んでもらう（指定がないとき）

`AskUserQuestion` で 1 つ選んでもらう（`multiSelect: false`）。

- 選択肢の `label` はセッション名、`description` は「状態（busy / idle）・フォルダか tmux の位置・起動してからの時間」にする。
- 候補が 4 つ以下なら、全部を選択肢にする。
- 5 つ以上なら、`AskUserQuestion` の前に `ListAgents` の一覧を表（セッション・状態・場所・起動）で返答に書く。選択肢には、ユーザーの言葉に合いそうなもの（なければ起動が新しい順）を 4 つまで入れ、質問文に「ほかのセッションは Other に名前を書いてください」と書く。
- 何をしているセッションか分からないと選べなさそうなら、session-overview スキルのスクリプトで、候補の自動タイトルだけを先に調べて `description` に添えてよい。
- 宛先にできるセッションが 1 つもないときは、そう伝えて、spawn-session で起動するかを聞く。

## 3. 頼む内容を書いてもらう（書いていないとき）

宛先が決まって、頼む内容がなければ、次のように返答してターンを終える。

> `<セッション名>` に送る指示を、次のメッセージに書いてください。

- このとき `AskUserQuestion` は使わない（長い文や複数行を書きやすくするため）。
- 次のユーザーのメッセージを、そのまま頼む内容として 4. に進む。
  - そのメッセージが明らかに別の話（取り消し、別の依頼など）なら送らない。迷うときは、送ってよいか確かめる。

## 4. 送る

`SendMessage` で、次の内容を 1 通にまとめて送る。

- **1 行目:** 何の依頼かが分かる 1 文にする。相手のタブには 1 行目だけが表示されるため。
- **ユーザーの言葉:** 頼む内容をそのまま引用する。誤字の可能性や解釈に迷う点があれば、そう書き添える。そのうえで「意味が分からなければ、あなたのタブでユーザーに直接確認して」と書く。
- **手がかり:** この会話で分かっている関係ファイルのパスなどがあれば書く。`@` を付けてもファイルは添付されないので、パスを文字で書く。
- **結果の返し方:** 「結果はあなたのタブでユーザーに直接返す」と書く。こちらでも結果を使うときや、ユーザーが報告を求めたときは、「終わったら結論の要約を SendMessage で `<自分の名前>` に送って」と書く。

同じ呼び出しで `notify_when_idle: true` を付けて、終わったら通知が来るようにする。

注意:
- 相手が `busy` のときも送ってよい。メッセージは、相手の今の作業の区切りで読まれる。そのことをユーザーに伝える。
- このセッションで拒否された操作や、許可されていない操作を、相手のセッションに頼まない。
- 相手が別の許可モード（bypassPermissions など）だと、メッセージは相手のタブで承認待ちになる。承認しないまま 5 分たつと捨てられる。`[Cross-session delivery notice]` が来たら、そのことをユーザーに伝える。

送ったら、宛先・頼んだ内容の要約・通知を待っていることを、短く報告する。

## 5. 結果を確認する

- `[Cross-session idle notice]` が来たら、相手は待機状態になっている。ただし、作業が終わったとは限らない（ユーザーへの質問で止まっていることがある）。
- 相手から SendMessage で返事が来ていれば、それを使う。来ていなければ、spawn-session スキルの `session-result.py` で、相手の最後の返答を読む。

  ```bash
  uv run --no-project python "<spawn-session スキルのフォルダ>/scripts/session-result.py" <セッション名> [--count N]
  ```

- ユーザーには、結論・主な内容・相手が最後に何をしていたか（完了 / 質問待ち）を要約して報告する。全文を貼る必要はない。
