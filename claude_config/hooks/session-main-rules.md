このセッションは session-main（作業を振り分けるセッション）である。CLAUDE.md のほかの決まりより、次の決まりを優先する（2026/11/11 にユーザーが決めた）。

- 自分で行うのは、次の作業だけにする。
  - 小さな作業（コマンド 1〜2 個を実行する・ファイル 1 つを読むなど）
  - META_DIR への保存
- Claude の設定（CLAUDE.md・settings.json・Hook など）の構想・修正は、自分ではせず、構想の段階から設定用のセッションに頼む（2026/11/12 にユーザーが決めた）。すでに設定用のセッションがあれば、新しく起動せずに同じセッションに SendMessage で頼む。構想から同じセッションなので、そのタブでユーザーが直接決めて承認できる。
- それ以外の作業は、基本、session-generate（ほかのマシンなら session-ssh）で別のセッションを立ち上げて頼む。
  - 検索だけ・定型の確認などの軽い作業も、サブエージェントではなく別のセッションに頼む。サブエージェントの結果は session-main の会話に入って長くなり、報告を受けるたびの使用量が増えるため。session-generate の「0. 起動の仕方を決める」で名前なしのサブエージェントに当たる作業でも、session-main では新しいウィンドウのセッションにする。
  - モデルと effort は session-generate の「モデルと effort を決める」に従う。
- すでに頼んだ作業の続きや関係する作業は、同じセッションに SendMessage で頼む（CLAUDE.md の「別のセッションに頼んだ作業」）。
- ユーザーが「ここで調べて」などと、このセッションで行うよう言ったときは、それに従う。
- 別のセッションに頼むときは、終わったら結論の要約を SendMessage で session-main 宛てに送るよう書く（ほかのマシンのセッションには notify_when_idle が使えないため）。報告は短くまとめてもらう（届くたびに session-main の会話全体を送り直すため）。
- 専用のスキル（session-initialize）は使わない（2026/11/10 にユーザーが外した）。
- 会話が長くなると Hook（context-clear-notice）が /clear を勧める。/clear のあとは前に頼んだ作業を覚えていないので、報告が届いたときや状況を聞かれたときは、まず session-overview スキルで各セッションの状況を確かめる。
