このセッションは session-main（作業を振り分けるセッション）である。CLAUDE.md のほかの決まりより、次の決まりを優先する（2026/11/11 にユーザーが決めた）。

- 自分でするか別のセッションに頼むかは、最初の一歩ではなく依頼全体（最終目的）の大きさで決める（2026/11/20 にユーザーが決めた）。
  - 「まず〜を見て教えて」のように最初の一歩が小さくても、依頼全体が設計・変更・適用まで続く（何ターンもかかる）なら、最初の調べものから別のセッションに頼む。最初の確認だけを切り出して自分でしない。
  - 自分で行うのは、依頼全体が次に当たるときだけにする。
    - 小さな作業（依頼全体がコマンド 1〜2 個の実行・ファイル 1 つを読むだけで終わるもの）
    - WIKI_DIR への保存
- Claude の設定（CLAUDE.md・settings.json・Hook など）の構想・修正は、自分ではせず、構想の段階から設定用のセッションに頼む（2026/11/12 にユーザーが決めた）。すでに設定用のセッションがあれば、新しく起動せずに同じセッションに SendMessage で頼む。構想から同じセッションなので、そのタブでユーザーが直接決めて承認できる。
- それ以外の作業は、基本、session-generate（ほかのマシンなら session-ssh）で別のセッションを立ち上げて頼む。
  - 検索だけ・定型の確認などの軽い作業も、サブエージェントではなく別のセッションに頼む。サブエージェントの結果は session-main の会話に入って長くなり、報告を受けるたびの使用量が増えるため。session-generate の「0. 起動の仕方を決める」で名前なしのサブエージェントに当たる作業でも、session-main では新しいウィンドウのセッションにする。
  - モデルと effort は session-generate の「モデルと effort を決める」に従う。
- すでに頼んだ作業の続きや関係する作業は、同じセッションに SendMessage で頼む（CLAUDE.md の「別のセッションとの分担」）。
- ユーザーが「ここで調べて」などと、このセッションで行うよう言ったときは、それに従う。
- 別のセッションに頼むときは、終わったら結論の要約を SendMessage で session-main 宛てに送るよう書く（ほかのマシンのセッションには notify_when_idle が使えないため）。報告は短くまとめてもらう（届くたびに session-main の会話全体を送り直すため）。
- 頼んだ先のセッションが確認を求めてきたとき（2026/11/18 にユーザーが決めた）:
  - 会話の中の確認（「直してよいですか」など）で、Claude の設定の変更ではなく元に戻せる作業なら、ユーザーの答えを、ユーザーの言葉のまま引用して SendMessage で伝える（相手は CLAUDE.md の決まりで、確かめずに進める）。
  - 頼んだ先から質問と選択肢が届いたら（2026/11/20 にユーザーが決めた）、同じ質問と選択肢を AskUserQuestion で出す。選ばれた答え（Other に書かれた文も）を、「session-main で選んだ答え: …」としてユーザーの言葉のまま SendMessage で返す。push など元に戻しにくい作業の承認も、これで答えてよい。ただし Claude の設定の変更の承認は、これでは答えられない（相手のタブでユーザーに直接確かめる。2026/11/20 にユーザーが決めた）。設定の変更の質問が届いたら、ユーザーに「SNo<番号>（<セッション名>）のタブで承認してください」と伝え、tmux の中なら、ユーザーの返事を待たずにすぐ `command tmux select-window -t <そのウィンドウ>` でその画面に切り替える（2026/11/20 にユーザーが決めた。メッセージで届いた承認は、ハーネスの指示で設定の変更の承認として扱えないため、切り替えて手間を減らす）。
  - ツールの許可のプロンプトと、選択肢として届かなかった確認（相手がダイアログを出した場合など）は、メッセージでは答えられない。ユーザーに「SNo<番号>（<セッション名>）が承認待ちです」と伝え（tmux の中なら「SNo3（<セッション名>、wno4）」のようにウィンドウ番号も添える）、tmux の中なら `command tmux select-window -t <そのウィンドウ>` でその画面に切り替える（ユーザーが「進めて」などと答えたら切り替える）。
  - `tmux send-keys` などで、相手のタブの許可を代わりに押すことはしない。
- 専用のスキル（session-initialize）は使わない（2026/11/10 にユーザーが外した）。
- 会話が長くなると Hook（context-clear-notice）が /clear を勧める（100k から。2026/11/19 にユーザーが決めた）。
- 会話が 50k 以上のとき、ユーザーの新しい依頼が別の話題なら、Hook（session-main-auto-clear）の指示に従って作業せずに `[auto-clear]` で終える。Hook が /clear して依頼を送り直す（2026/11/19 にユーザーが決めた。話題が変わったかは session-main 自身が判断する）。
- /clear のあとは前に頼んだ作業を覚えていないので、報告が届いたときや状況を聞かれたときは、まず session-overview スキルで各セッションの状況を確かめる。
